# Web 右键菜单与手机长按兼容

2026-10-12 对已登录的 Windows 实机排查后，确认聊天菜单取得 15 个菜单项，却在菜单自动取得焦点时立即关闭。原因是异步菜单用捕获阶段监听 `window.blur`，把聊天行的元素失焦也当成窗口失焦。

本次修复保留官方菜单、权限过滤、菜单项与操作回调：

- 窗口失焦监听不再使用捕获阶段；窗口真正失焦、再次点击、再次右键和 Escape 仍取消等待中的菜单，AbortSignal 仍负责清理监听。
- 官方 DOM 菜单触发器使用 `display: contents` 容器接收事件，避免复合聊天行丢弃注入的 pointer/key 属性。子节点先执行原处理器，容器阻止事件继续触发外层菜单。
- 聊天行的 ContextMenu / Shift+F10 定位到实际行；已有事件取消、修饰键和原生菜单分支保持不变。
- 手机侧栏触摸只标记为跳过拖拽传感器，不再阻断事件传播。长按延迟和移动、松手、取消行为继续使用官方 Radix 实现。
- Page 引用不再因为 Web 环境缺少原生菜单接口而直接退出，继续使用原版“复制链接”和“在外部浏览器打开”菜单。

补丁只接受唯一匹配的已审计代码结构，重复或变化的结构原样保留并输出诊断。静态资源补丁版本由 16 更新为 17，以使已有资源缓存失效。

## 手机菜单与设置分类布局（2026-10-12）

根据 Android ARM64 测试设备上的 Chrome 窄屏截图调整布局：

- 聊天上下文菜单和项目子菜单改为屏内单列底部面板，操作行至少 52px；长路径换行，子菜单覆盖父菜单并提供返回入口。原来的菜单项、权限与回调不变，返回/关闭委托原生键盘处理器；返回前先显示父菜单以恢复焦点。单面板通过点击或键盘打开子菜单，避免鼠标悬停提前替换点击目标。
- 仅 Radix ContextMenu 使用上述布局。账号下拉菜单单独定位到抽屉底部账号按钮上方，避免越界和松手误选；模型等其他下拉菜单保持原定位。
- 设置分类由“设置分类 · 当前分类”入口展开原生按钮的两列网格；搜索时展开、选择后收起。分类区域自行滚动，Esc 仅在焦点位于分类导航内时收起，避免阻断其他弹窗。
- 输入区加宽、项目名称恢复显示、设置说明字号和间距调整。宽屏或禁用移动侧栏插件时移除增强节点与标记，恢复原布局。

浏览器预览覆盖 393×760、360×420 和 1100×800：项目面板左侧约 12px、右侧约 381px，内容 scrollWidth 与 clientWidth 相同；项目子菜单返回、菜单关闭、原生重命名弹窗及取消正常；设置搜索、选择外观、自动收起与宽屏清理正常；账号菜单完整位于屏幕内且打开不触发操作。短视口用于验证可用空间，不等同于真机软键盘实测。

构建及 46 项菜单/手机定向检查通过（含 5 项新增面板行为测试），4 项需要外部完整 bundle 的检查未配置而跳过。测试覆盖原生节点保留、父子面板遮盖、返回/关闭键委托、LTR/RTL 返回前恢复可见性、仅拦截手机子菜单鼠标悬停、设置搜索/选择/Esc 范围及禁用/断连/关闭/销毁清理。
