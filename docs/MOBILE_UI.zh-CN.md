# 手机 UI 适配

验收日期：2026-10-11（Asia/Shanghai）。针对 Codex 26.1007 的 OWL 界面；这是浏览器布局增强，不代表所有官方业务功能已完成移动端验收。

## 交互设计

- **手机单栏 + 底部导航**：复用官方六个导航按钮和状态，显示原生本地化标签，不复制 React 节点。
- **全宽侧栏抽屉**：继续使用官方展开/收起开关。关闭时透明容器不拦截聊天区域点击。
- **紧凑顶栏**：为侧栏开关、新标签和右侧面板入口保留空间；手机上隐藏无效的前进/后退及主面板分屏切换。
- **触控输入**：顶栏、底栏及输入区的主要操作目标至少 44px，输入文字 16px；模型菜单和表单限制在视口内。
- **短屏优先输入**：横屏或键盘压缩后收起首页装饰，而不是把输入框推出屏幕。
- **安全区与键盘**：复用既有共享视口协调器。Android 根据聚焦和实际高度损失判断键盘；仅聚焦、硬件键盘、旋转和双指缩放不会被当作软键盘。iOS 继续由既有 iOS 修复插件负责。
- **允许缩放**：登录页和主界面的 viewport 不再禁用双指缩放；移除移动插件的缩放阻断监听。

设计参考：[CloudCLI / Claude Code UI](https://github.com/siteboon/claudecodeui) 的移动触控导航，以及 [codex-web](https://github.com/windoze/codex-web) 的小屏会话抽屉与表单交互；同时调研了 [Happy](https://github.com/slopus/happy) 的移动使用场景。仅借鉴交互思路，没有复制这些项目的源码。

## 实现边界

- 独立样式：[codex-mobile-layout.css](../web-shell/codex-mobile-layout.css)。使用官方语义属性定位，所有规则限定在媒体查询内。
- 手机范围：宽度 ≤767px；横屏补充：宽度 ≤960px 且高度 ≤500px。平板竖屏与桌面保留原导航布局。
- [静态资源服务](../gateway/runtime/http/static-assets.cjs) 在官方样式之后注入唯一 stylesheet；固定路径映射，不扩大文件访问权限。沿用 ETag 与重新验证，不增加离线缓存。
- [移动键盘插件](../web-shell/internal/providers/mobile-keyboard-optimization.js) 发布键盘可见标记，不新增独立视口监听器。禁用/卸载时清理标记及高度基线。
- [路径选择弹窗](../web-shell/codex-workspace-root-picker.css) 在 ≤640px 时采用底部抽屉与安全区留白。保留现有协议及焦点行为，不改变目录选择业务。
- 不修改官方安装包、鉴权策略、模型发送/审批处理或用户配置。

## 验证结果

在已安装的真实网关页面上，用 Chromium 浏览器视口检查以下尺寸：

| 类型 | 尺寸 |
| --- | --- |
| 手机竖屏 | 320×740、360×800、390×844、430×932 |
| 手机横屏 | 844×390 |
| 平板 / 桌面 | 768×1024、1280×800 |

- 七种尺寸均未出现整页横向溢出；手机的顶栏、底栏与输入区按钮中心点可实际命中，输入区在导航上方。
- 验证了侧栏展开/关闭、模型菜单以及创建项目对话框布局；未发送测试消息、创建项目或改变模型设置。
- 触屏模拟：390×844 聚焦时底栏保留；同宽缩为 390×420 时键盘标记为真、底栏隐藏、输入区仍可见；恢复高度和切换横屏后底栏恢复。
- 创建项目对话框在 390px 宽视口内，输入容器及按钮高 44px，文字 16px。
- gateway 构建、类型检查与修改边界检查通过。新增 18 项测试通过：5 项布局、8 项键盘状态、5 项静态集成。
- 定向回归共 93 项：92 通过，1 项既有失败（诊断页中文标题断言仍期望旧文案）。扩展性能回归共 126 项：112 通过、14 失败；额外 13 项为既有源码标记断言，基线复测同样失败。本次未修改或跳过这些无关断言。

独立布局与键盘回归可运行：

```sh
node --test gateway/test/mobile-layout.test.cjs gateway/test/mobile-keyboard-state.test.cjs
```

## 尚未验证

- 上述触屏与键盘测试是浏览器模拟，不是真实 iPhone Safari / Android 设备的系统软键盘、刘海安全区或 PWA 测试。真机旋转、输入法切换和多行长消息仍需补充验收。
- 本轮未使用真实模型生成长会话，也未对审批、终端和所有业务页面做端到端移动验收。
- 当前版本“创建项目 → 添加”未在浏览器中打开 Web 路径选择弹窗。因此路径选择样式已覆盖，但不能声称此入口的目录选择流程已经跑通；其桥接协议需要单独验收。
- 后续官方 DOM 标记变化可能需要更新样式定位。不要以替换用户内容或禁用鉴权规避适配问题。
