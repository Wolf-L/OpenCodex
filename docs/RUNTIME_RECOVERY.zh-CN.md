# Windows / Linux 运行时恢复：第一批

本批处理启动缓存损坏与启动阶段的来源一致性。官方安装目录只读，测试故障仅注入临时夹具。

## 已实现

- Portable runner 在隔离目录复制资源、生成 gateway ASAR、修正 Windows PE integrity；全部成功后才切换目录并发布清单。准备失败保留旧目录，清单发布失败恢复旧目录。
- 缓存复用检查 EXE 与 gateway ASAR 的 SHA-256，以及配套文件是否存在、类型和大小是否正确。缺失或截断 DLL/locale、损坏 EXE 会重建一次；源本身无效则明确报错。
- 官方资源指纹递归记录子文件，捕获子目录 mtime 未变的资源更新。缓存命中不重写 EXE/ASAR；Windows 根级程序集清单继续使用已有的普通读写修复方式。
- Windows EXE 补丁完整写入同目录临时文件后替换，拒绝目标与官方 EXE 是同一实体或硬链接的情况。
- 父进程先选定 bundle，再选择配套 Electron；子进程验证清单、安装来源与可执行文件摘要，不重新扫描。CLI 环境变量也固定为本轮选定来源。
- 新 bundle 清单保存 ASAR、unpacked 资源树和 CLI 内容摘要。关闭扫描或还原时发现来源不符会拒绝启动，避免混用缓存。还原使用独立固定标志，优先于 Linux 的显式安装/CLI 路径。
- 备份状态轮询只检查轻量元数据；实际还原和启动进行内容校验。
- Windows、Linux x64、原生 Linux ARM64 CI 均运行完整测试入口，再执行打包。

## 验证

- 本批新增 27 项故障恢复和来源绑定测试，覆盖写入中断、清单发布失败、损坏缓存、准备期间源变化、Linux 显式路径与回滚固定，以及 Electron 物理 ASAR 读取。
- Windows 全量 `pnpm test`：723 项，712 通过、0 失败、11 跳过；构建和 TypeScript 检查由 pretest 完成。跳过项目依赖特定平台或可选官方 bundle，不能视作实机通过。
- 之前 19 个基线失败已修复：CRLF 源码定位、测试内跨平台路径/POSIX 权限假设，以及过期文案/模型默认值。行为断言保留，未以跳过失败用例代替修复。

## 边界与后续

- 此批尚未实现 Electron、bundle、CLI 和外部官方资源的完整离线版本快照，也未提供真实启动成功后再切换全部组件的事务。旧官方安装被删除或替换后，不能保证旧 bundle 可回滚启动。
- 历史清单只有 ASAR size/mtime 基线；正常扫描刷新后才升级为内容摘要。该历史基线无法证明 native/CLI 未被单独替换。
- Portable 资源文件校验类型/存在/大小；同大小的资源内容损坏不在该缓存检查范围内。源资源指纹仍依赖路径、大小和修改时间。
- 文件被 Windows 锁定导致目录切换失败时保留原目录并报错。未增加跨进程准备锁，不支持并发向同一运行目录准备多个版本。
- 内容摘要增加启动时磁盘读取；本批未声明启动性能提升。状态轮询不会反复读取大型安装包。
- Linux ARM64 的原生打包/测试以对应 CI 结果为准；Windows 上的 Linux 夹具不代表 ARM64 真机运行验证。
