# Windows 本体更新

此功能更新 **OpenCodex 应用本体（含 Electron）**，与设置中的“Codex 官方运行时”预检、版本切换独立。不会下载或分发官方 Codex 二进制。

## 使用范围

- 首批支持 Windows x64、NSIS 登记的当前用户安装，安装目录名为 `OpenCodex`。安装前核验精确应用 GUID、安装/卸载路径及打包后保留的包名、产品名、入口和版本；electron-builder 会移除 `package.json` 的开发用 `build` 字段，不能以它作为唯一身份依据。
- 仅选择固定项目仓库较新的稳定 semver 发布；同一发布须包含 `OpenCodex Setup <版本>.exe` 和 `opencodex-update-win32-x64.json`。
- macOS、Linux、便携或无法验证的安装方式保留发布页入口。缺少清单的历史版本也不会启动自动下载。

## 分阶段操作

1. **检查更新**：只读取发布元信息，不下载或停服。
2. **下载并校验**：当前服务继续运行；显示进度，可取消并从头重试。清单限制 64 KiB，安装包限制 1 GiB，使用受限 HTTPS 重定向、总时限和停滞时限；拒绝不匹配版本、平台、大小和摘要。完成文件落盘后才显示安装按钮，应用重启后需重新下载。
3. **安装并重启**：重新校验安装包，锁定服务/设置更新操作；保存完整应用树、摘要清单和两个应用专属 HKCU 注册键。独立复制并重命名的 Electron 宿主在安装目录外启动助手，READY 后 Launcher 才等待 Gateway 真正退出并许可安装。
4. **启动确认**：NSIS 退出 0 不等于成功。助手显式启动新版，核对事务令牌、目标版本、EXE、进程身份和 Gateway 归属；新版必须完成已有监督启动检查才写入确认。Gateway 身份须在候选启动器存活时取得并复核，不能在父进程消失后仅凭旧 PID 接管进程。
5. **失败恢复**：助手运行期间的安装/启动失败，先确认属于本事务的进程退出，再恢复完整应用及登记信息并启动旧版。无法证明退出、备份损坏或中断事务则保留现场，不覆盖当前文件、不循环安装。

## 数据与恢复边界

事务位于 Launcher 用户目录的 `self-update/transactions/<事务ID>`；包括 `journal.json`、完整 `application-backup`、注册备份及 `recovery-notes.txt`。失败新版目录可能保存在安装目录旁的 `.failed-update-<事务ID>`。不自动删除备份或失败现场。

备份和清单按物理文件字节处理，包括完整 ASAR 归档。正常 Electron 主进程和安装目录外的 Electron Node 模式助手均使用内置 `original-fs`，普通 Node 宿主使用 `node:fs`，避免虚拟 ASAR 文件系统把备份展开或改变摘要。

应用恢复不快照账号、会话、官方运行时、用户配置或数据库，也不能撤销新进程已经执行的数据迁移和外部副作用。断电、助手被强杀或进程归属不明时没有无人值守恢复；界面明确提示保留备份检查，不显示不可用的“自动恢复”按钮。人工处理前必须核对事务日志、备份完整性和真实进程，不能仅删除锁文件后重试。

校验摘要与安装包来自同一 HTTPS 仓库，只提供一致性检查，**不是代码签名或独立发布者认证**。不关闭 Windows 安全保护，不擅自获取签名证书。NSIS 静默调用只发生在用户明确点击安装之后，不传 `--force-run`，防止安装器与助手重复启动程序。

## 发布产物

CI 在真实 Windows NSIS 包生成后运行 `scripts/create-windows-update-manifest.cjs`，将版本、平台、架构、appId、提交和实际安装包大小/SHA-256写入清单，与 EXE 一起上传。创建草稿发布前再次校验清单与文件。普通功能提交不升级版本、不自动公开发布。

## 验证范围

- 自动化测试覆盖流式取消/超时/内容损坏、路径与发布身份限制、重复操作、停服失败、安装失败、错误确认、备份损坏及恢复时保留用户数据。
- Windows 真实隔离实验验证了独立测试应用 1.0.0 → 1.0.1 的 NSIS 当前用户静默安装、同目录更新、无强制自启动及用户数据保留；另以复制的真实 Electron 宿主验证了准备、READY、取消。
- 上述模拟故障测试和真实机制实验 **不等于生产端到端线上更新/回滚验收**。当前尚无可供此链路测试的公开 Windows 稳定发布；首次正式发布后仍需完整验证下载 → 安装 → 启动确认与故障回退。
