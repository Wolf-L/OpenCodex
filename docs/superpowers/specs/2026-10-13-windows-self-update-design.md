# Windows 本体更新事务

本阶段落实已确认的 Windows 优先更新路线；用户将实现选择交由代理，不再逐项确认。macOS/Linux 暂保留发布页入口，不更改版本、不自动发布 release。

## 方案选择

- 不把已有“官方运行时版本切换”冒充本体更新：本体安装还会替换 Electron 和卸载信息。
- 不直接引入默认自动行为的通用更新器；现有非标准发布标签和独立运行时需要受控发现流程，且启动失败恢复不是通用更新器提供的现成功能。
- 采用现有固定仓库检查 + 受限流式下载 + 外部安装事务助手，复用当前 NSIS 安装包。仅支持已识别的 Windows x64 当前用户安装；无法验证身份时保留手动发布页。

## 数据和控制流

1. CI 在真实 NSIS 包生成后发布独立 `opencodex-update-win32-x64.json`，包含 schemaVersion、appId、版本、平台、架构、安装包名称/字节数/SHA-256、提交。Release 仍只创建草稿。
2. Launcher 从同一发布选择清单和安装包；渲染器只调用无参数动作，不传入地址、路径或摘要。无清单的旧发布仍可手动打开，不允许自动下载安装。
3. 下载在用户目录的专用更新子目录内进行，当前服务继续运行。限制 URL、重定向、流大小、总体时限与停滞时限；支持进度、取消和从头重试。完整性通过后 fsync/rename 发布 ready 文件；安装前再次计算摘要。
4. 安装阶段设置全局生命周期互斥，外部助手准备完整应用树及注册信息备份并就绪后，主进程等待 Gateway 真正退出，再许可助手安装并退出。无法退出则取消安装、保留原服务状态。
5. 助手位于安装目录外，使用独立复制并重命名的运行宿主；不依赖即将被卸载的旧文件，不与 NSIS 同时启动新程序。安装器退出 0 不代表更新成功。
6. 新 Launcher 通过随机事务令牌、目标版本、执行路径、新进程身份和监督 Gateway 启动确认写 ACK；助手验证 ACK 后提交。新版失败则仅终止本事务拥有的进程、确认退出，再恢复完整应用文件与保存的卸载信息，重新启动旧版。
7. 进程无法确认退出、备份损坏或中断事务不能证明安全时保留备份并报告需要恢复，不盲目覆盖、不循环安装。原子日志不是文件系统/注册表跨资源断电事务。

## 不变项与信任边界

不删除旧备份，不更改用户账号、认证配置、聊天、官方安装与运行时快照。摘要来自同一 HTTPS 仓库发布，只证明一致性，不伪称代码签名或独立发布者认证。没有签名证书时不擅自注册、购买或修改系统安全设置。NSIS 注册信息恢复只覆盖已识别当前用户安装相关键，不能影响其他软件。

## 验证与交付

使用真实文件、受控进程和故障注入覆盖下载取消/损坏/超时、重复操作、退役失败、安装失败、错误版本/令牌、启动失败、备份损坏和数据保留。生成器对 CI 实际安装包复核；可行时在隔离应用身份/目录验证真实 NSIS 安装，不覆盖生产注册表。全量检查和跨平台 CI 后按既有授权备份更新本机。公开仓库当前没有 Windows 稳定发布，不能把本机代码部署或模拟安装称为线上升级已验证。
