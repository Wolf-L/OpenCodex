# 第四阶段 B：Gateway 持有 App Server 连接

日期：2026-10-13（Asia/Shanghai）。基线：`6cec4a1`。

用户已在聊天中确认 4B 的组件归属、共享连接、私有过滤、启动失败及退出验证方案，并明确要求实施。本稿落实该方案，不再重复询问已确认的方向。

## 边界

本阶段迁移生产启动链路的传输创建与销毁所有权。官方 Electron/app-host/CLI、账号、配置、会话、网络入口、模型选择及审批语义不变。不实现独立后端或插件热卸载，不修复缺失 rollout，不宣称性能提升。

## 组成

- 新增 Gateway 装配模块 `runtime/app-server-service.cjs`，创建唯一通用 transport，装配路由策略、插件服务、历史预览，并统一销毁。该模块位于通用 `app-server/` 目录之外；通用目录仍不反向导入路由、插件或 Electron。
- 新增通用消费者作用域 `app-server/client.cjs`：消费者仅获得请求/观察能力，不获得装饰子进程、关闭连接或拒绝全部请求的权限。关闭作用域只取消自己的请求、通知等待和订阅。
- 通用 transport 增加可选 AbortSignal，仅取消本地等待，不撤回已交给系统的写入，不重试或重放。所有成功、错误、超时、取消及断开路径清理 signal 监听。
- 路由 transport 兼容入口复用一个私有能力适配器；生产路由服务使用注入的作用域，不创建或关闭共享连接。旧独立构造入口保留原来的自持有模式，以兼容既有调用及测试，不复制另一套传输实现。
- 历史预览使用独立只读客户端，并显式注入内部线程排除函数；不再通过 `pluginService.modelRouter.transport` 获取连接。旧调用的可选过滤接口继续兼容。

## 生命周期

Gateway 在启动官方 runtime 之前完成全部装配，随后使用 owner 的 decorator。路由的附着/关闭回调仍在原语义位置报告已有兼容点；Auto 开关不控制通用连接，也不撤掉私有过滤策略。

私有登记、tombstone、迟到清理属于连接代际，保留到该代际退役；路由消费者的 dispose 不清空共享策略。消费者销毁后迟到结果不得重新填充缓存、发布路由状态或继续分类。内部线程列表在 request 完成前先按原代际过滤，避免 Promise 续体与替换交错；路由队列在入队时绑定生命周期修订号，不在旧工作开始执行时借用新修订号。仅销毁消费者不是热卸载功能；已进入停止状态的路由 middleware 不再接收新业务帧。

owner 内部正常退出顺序：历史预览及其客户端 → 插件/路由及其客户端 → 通用 transport → 既有其余 Gateway 资源。owner 幂等，某个消费者清理抛错也必须继续释放其余资源。创建中途、官方 bootstrap 或后续启动失败均走 owner 清理，保留最初错误和已有离线诊断落盘逻辑。transport 不 kill 官方进程。

## 保持的契约

保留既有请求前缀、方法排序规则、64 帧背压、超时、代际隔离、5 分钟/512 条 tombstone、历史预览的 700ms 导航预算和缓存策略。兼容点 ID/数量不变；路由装饰器的诊断仍表示该策略已接入，不伪装成模型可用性检查。

## 验收

先以 fake child、可控请求、独立临时配置测试消费者释放不影响其他消费者、取消后的私有迟到响应仍被隐藏、Auto 关闭仍能读取历史、创建/启动失败清理、退出次序及幂等。覆盖 signal 监听释放和复用连接不被消费者关闭。

运行原有传输、路由、历史、健康、启动及兼容回归，再执行完整 pnpm test（含类型/边界）和五平台 CI。按已授权流程备份并更新本机，校验变更文件、IPC/CLI/兼容健康、prepare 锁；实页检查主页、历史、模型目录和草稿连接面板。不发送测试消息，不修改真实会话。
