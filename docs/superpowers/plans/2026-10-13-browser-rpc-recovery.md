# RPC 恢复实施计划

用户已于本轮明确选择“继续实现 RPC 恢复”。writing-plans 技能在已知技能目录未安装，采用此手工计划；不重复询问已经批准的方案。

1. 新增独立内存会话管理器及失败先行测试：认证绑定、双向连续计数、原端口复用、未发送下行队列、90 秒期限及容量、迟到旧连接、退出清理。
2. WS hub 通过 hello 协商版本、带序号封装 app-host 控制/数据帧，旧客户端保留旧协议。服务退出释放所有恢复会话。
3. 浏览器只恢复原会话，不重建旧 RPC；收到缺口/失效明确关闭恢复，禁止旧队列冲刷。UI 分开报告 Gateway 与应用通道，并提供用户主动重新加载入口。
4. 有状态 RPC 集成夹具与浏览器 VM 回归，覆盖旧引用、无重复调用、初始排队、Gateway 重启及隐私隔离。
5. 完整检查、五平台构建、备份更新本机。实页以仅当前测试标签页的心跳故障验证同页恢复、历史/模型可用及草稿保留；失效场景必须明确提示，不自动刷新或发送消息。清理测试探针/自建文字，保存证据。

全局约束：不改官方文件、账号、访问权限、真实会话或磁盘格式；不自动重发已发送帧；序号不足以证明连续性时失败；只恢复同一 Gateway 进程内的原会话。离线最多 32 会话、90 秒、单会话 1 MiB/256 帧、总计16 MiB，正常连接大帧保持原限制。恢复标识仅内存，不进日志/URL。代码增加中文注释，英文 Conventional Commit。
